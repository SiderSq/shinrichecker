# Shinri · Lobby Checker

Локальное приложение для проверки участников Danganronpa Online по отзывам shinrireviews.com.
Поддерживает браузерный интерфейс, Windows-окно и CLI. Оценки описывают отзывы сообщества;
они не гарантируют уровень игры, поведение или исход матча.

## Установка и запуск

Python 3.10+:

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.lock
python main.py --browser
```

Откройте адрес, напечатанный при запуске (по умолчанию http://127.0.0.1:8088).
Для отдельного окна Windows дополнительно установите `pip install ".[desktop]"` и запустите `python main.py`.
Для сборки Windows установите `pip install ".[desktop,windows-ocr,build]"` и выполните `python build_exe.py`.
Браузерный интерфейс работает на других ОС; Edge WebView2 и WinRT OCR требуют Windows.

## Интерфейс

- Светлая/тёмная тема: первоначально системная, выбор сохраняется локально.
- Две панели: ввод состава и результаты с числом найденных профилей, оценённых игроков и записей к проверке.
- Ввод ников, ссылок и ID (`#3865` тоже поддерживается), файлов TXT/CSV и логов чата.
- Автопересчёт при 16 строках; готовность определяется сервером по уникальным разрешённым профилям.
- Поиск, сортировка, история составов, замена игрока и текстовые отзывы.
- Омонимы по умолчанию требуют ручной проверки. Автовыбор по числу отзывов включается явно.
- Дубликаты и неразрешённые профили не считаются готовым матчем.

## OCR

Изображения обрабатываются локально; сторонним OCR-сервисам они не передаются.

1. Windows: `pip install ".[windows-ocr]"`; установите системные языковые компоненты OCR ru/en.
2. Резервный движок: установите **Tesseract OCR** отдельно с моделями `rus` и `eng`; команда `tesseract` должна быть доступна в PATH.
   Например, Ubuntu: `sudo apt install tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng`.
3. Вставьте изображение Ctrl+V, перетащите файл или выберите его. Макеты: автоматический, сетка карточек 2×8/1×8, таблица/текст.
4. Проверьте сомнительные кандидаты: доступны исходный OCR-текст, альтернативные профили и явное подтверждение.
   Неподтверждённые кандидаты не переносятся в состав. Подтверждённый профиль передаётся по ID, а не повторно сопоставляется по нику.

Лимиты: 8 МБ, 20 мегапикселей, 12000 пикселей по стороне; бюджет OCR — 25 секунд. Учитывается EXIF-ориентация и прозрачный фон.

Перед загрузкой можно включить «Сначала выделить область с никами». В этом режиме полное изображение не распознаётся: обведите ники мышью/касанием или задайте координаты в процентах, затем нажмите «Распознать снова». Оригинал не изменяется. Область применяется после EXIF-ориентации; минимум 12×12 пикселей.

Повторное OCR использует локальный кэш в памяти: до 8 результатов на 5 минут, без хранения изображений на диске. Ключ учитывает изображение, макет, область и версию базы. После обновления базы старые совпадения не переиспользуются; ошибки не кэшируются. Повторный ответ помечается «из кэша».

Процент сходства — сходство строк, **не вероятность правильной идентификации**.
Tesseract.js не включён; отсутствие движка сообщает ошибку с инструкцией установки.
Если скриншот плохо распознаётся, обрежьте область с никами, выберите макет «Текст» и проверьте профили вручную.

## Вид интерфейса

- «Настройки и история» свёрнуты по умолчанию; алгоритм оценки и обработка омонимов не изменены.
- На мобильном экране кнопка расчёта закреплена снизу; при открытии диалога панель скрывается.
- «Вид списка» переключает подробную/компактную плотность и сохраняет предпочтение локально. Оценки, отзывы и действия остаются доступны.
- Неоднозначные, ненайденные и повторные строки отображаются сначала в группе «Требуют проверки». Это только представление: баллы, номера мест, полный состав и порядок копируемого рейтинга не меняются.

Онлайн-клиент повторно использует ограниченный пул HTTP-соединений (urllib3). Сохранены проверки TLS, переменные окружения прокси/NO_PROXY, ограничения ожидания и политика повторов. После завершения сервера пул очищается.


## CLI

```sh
python main.py --cli -p "Hunk, mercyflower^-^" --balance-teams --lobby-safety --clans
python main.py --cli --input sample_players.txt --top 10 --ranking-mode bayesian
python main.py --cli --input sample_chat.txt --chat-log --manual-ambiguous
python main.py --cli --ocr screenshot.png
python main.py --cli --input sample_players.txt --tournament single_elimination
python main.py --cli --input sample_players.txt --export-csv results.csv --export-json results.json --export-md results.md
python main.py --cli --input sample_players.txt --offline
```

Аналитика использует полный уникальный состав, независимо от размера топа/антитопа.
Для игроков без рейтинга при балансировке используется явно помеченный средний приор, а не подтверждённая сила.
Плей-офф поддерживает 2–128 участников с BYE; групповой этап не отбрасывает остаток состава.
«Elo», шансы победы, индекс комнаты, анализ слов и клановых тегов — эвристики, не калиброванные модели.
Для калибровки нужны реальные результаты матчей; общий тег сам по себе не доказывает сговор.

## Кэш и локальный API

Импорт валидируется до публикации; запись JSON выполняется через временный файл и атомарное переименование.
`.dat` — необязательный версионированный gzip/JSON-кэш с контрольной суммой; старый marshal-кэш безопасно игнорируется.
Для чтения базы допустима папка без права записи, но импорт/обновление должны иметь доступ на запись.
Каталог игроков без отзывов сохраняется при обновлении; временный сетевой сбой не кэшируется как отсутствие профиля.

Сервер предназначен **только для loopback** (`127.0.0.1`/`localhost`), не для публикации в сети.
Есть проверка Host/Origin, токен сессии, запрет выхода из каталога статики и ограничения тела/параллельных запросов.
Для собственных локальных API-клиентов задайте переменную окружения `SHINRI_API_TOKEN` перед запуском
и передавайте её в заголовке `X-Shinri-Token`. Не добавляйте токен в репозиторий.

## Проверки

```sh
python -m unittest -v test_shinri test_hardening test_ui_text test_performance_layout
npm ci
npm run lint
npx playwright install chromium
npm run test:ui
npm run format:check
```

Браузерные тесты используют оффлайн-фикстуры, а OCR-ответы в UI-тестах замоканы — это не измерение точности движка.
Реальный тест скриншота задаётся через `SHINRI_OCR_FIXTURE`; без файла он пропускается.
Windows WinRT, WebView2 и сборку EXE необходимо отдельно проверить на Windows с установленными языками.
Версии runtime-зависимостей закреплены в requirements.lock; dev-зависимости JavaScript — в package-lock.json.
Windows-надстройки заданы диапазонами и не являются полностью зафиксированным окружением сборки EXE.
